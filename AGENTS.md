## Structure and ownership
- `docs/` contains dated plans, architecture decisions and verification notes. Keep prior plans.
- `src/shared/` contains IPC contracts and domain types; change contracts before implementations.
- `src/main/` owns Electron lifecycle, local persistence, PDF import and DeepSeek requests.
- `src/preload/` exposes narrowly scoped, typed IPC methods. Never expose raw Electron or filesystem APIs.
- `src/renderer/` contains renderer HTML and application code. `src/renderer/src/components/` contains view components; `src/renderer/src/data/` contains explicitly labelled samples. Renderer state-safety helpers and their tests live alongside `src/renderer/src/App.tsx`.
- `tests/` contains behavior tests; `scripts/` contains repeatable verification and packaging helpers.
- `out/` is generated by `npm run build` and may be overwritten by that command. `dist/` is generated by packaging and may be overwritten by that command. Do not run automatic cleanup.
- Screenshots and test artifacts go under the workspace-level `verification/` using `paper-reader-` prefixes, outside submission packages. Submission packages go under workspace-level `deliverables/`.
- Package dependencies are project-local. Do not install global packages or change system configuration.

## Data and safety
- Store imported copies and per-paper data in Electron's userData directory, separate from source and executable files. Never modify the original imported file.
- Use a stable paper ID and request ID to isolate documents and asynchronous responses.
- Persist notes before switching papers; serialize writes and use safe replacement for data files.
- No API keys, secrets, machine-specific paths or real user data in source, logs, commits, screenshots or distributions. No `.env` creation or modification.
- Let the user enter their own key in the desktop settings UI. Main-process encrypted storage may use Electron safeStorage; fail explicitly if encryption is unavailable. Never silently fall back to plaintext.
- Use sandboxed renderers, contextIsolation and a narrow validated IPC bridge. Keep nodeIntegration disabled. Do not render untrusted raw HTML.
- Ask Will before deletion, schema migration, git push/rebase/reset, system/global changes or public release. Build outputs may be overwritten only through the documented build commands.

## Verification
- `npm run typecheck` verifies TypeScript for the complete app.
- `npm test` runs meaningful local persistence and context-routing behavior tests.
- `npm run build` produces the production application bundle and locally bundled PDF worker.
- `npm run dev` starts the desktop application for interactive visual review.
- `npm run start` starts the built desktop application.
- `npm run package` builds and copies the Windows x64 Electron runtime and application into `dist/PaperReader-<package-version>-win32-x64/` (current target 0.2.0); it may overwrite generated files for that version but does not remove earlier versions or publish anything.
- Before claiming completion, inspect the actual Electron window and verify welcome/demo, PDF import, Reader/Summary, Chat/Note, notes recovery, settings and a narrower window. Record any verification that could not be completed.
- Do not claim live DeepSeek verification without an actual user-configured key and a successful request. Missing credentials must not block local reading or notes.
